# راهنمای تست

## ۱) تست‌های واحد Node (بدون نیاز به بک‌اند)

```bash
node --test "tests/unit/*.test.mjs"
```

پوشش: اعتبارسنجی slug، پارس قیمت فارسی، قالب‌بندی قیمت/ارز، اعتبارسنجی تصویر، شبیه‌سازی تریگرهای پلن (سقف محصول/دسته/برچسب)، قفل وضعیت اشتراک، view عمومی، auth و مسدودسازی ساخت کاربر برای غیرابرمدیر.

## ۲) تست‌های pgTAP ایزولاسیون و RLS (نیاز به پروژه واقعی)

یک‌بار روی پروژه Supabase:

```sql
create extension if not exists pgtap;
```

اجرا با psql:

```bash
psql "$SUPABASE_DB_URL" -f supabase/tests/rls_tests.sql
```

اسکریپت fixture می‌سازد، نقش‌ها را با `set_claim` شبیه‌سازی می‌کند و ۹ ادعا را بررسی می‌کند:
ایزولاسیون خواندن/نوشتن بین کافه‌ها، قفل `platform_role`، نبود دسترسی مستقیم anon به جدول‌ها، دسترسی anon به view عمومی، سقف پلن، قفل اشتراک منقضی، پنهان‌شدن کافه معلق، و نبود INSERT عمومی روی analytics.

> اگر pgtap نصب نیست، همین سناریوها را می‌توان با دو کاربر آزمایشی و تلاش دستی برای cross-cafe access در SQL Editor به‌صورت دستی تکرار کرد.

## ۳) تست دستی سفرهای کاربری (Manual journeys)

### منوی عمومی
- [ ] `/cafe/demo-cafe` منو را با دسته‌ها و محصولات نشان می‌دهد.
- [ ] slug ناموجود → صفحه «کافه پیدا نشد».
- [ ] جستجو نتایج و حالت «نتیجه‌ای پیدا نشد» را درست نشان می‌دهد.
- [ ] محصول ناموجود با برچسب «ناموجود» و خاکستری نمایش داده می‌شود (در کافه‌ای که hide_unavailable ندارد).
- [ ] «کافه شهر» (hide_unavailable=true) محصول ناموجود را نشان نمی‌دهد.
- [ ] تغییر زبان (کافه حرفه‌ای) نام‌ها/دسته‌ها را انگلیسی می‌کند و چیدمان LTR می‌شود.

### داشبورد کافه
- [ ] ورود با `admin@demo.cafe` → داشبورد کافه لم.
- [ ] افزودن/ویرایش/حذف محصول با تأیید؛ تصویر آپلود و در منو نمایش داده می‌شود.
- [ ] تغییر موجودی با toggle بلافاصله در منوی عمومی (پس از رفرش) اعمال می‌شود.
- [ ] سقف دسته (در دمو: موقتاً سقف را در دیتای دمو کم کنید) → پیام ارتقا، نه خطای خام.
- [ ] حذف دسته دارای محصول → دیالوگ «انتقال/حذف محصولات».
- [ ] تغییر slug با تأیید؛ QR جدید آدرس جدید را نشان می‌دهد.
- [ ] دانلود PNG و صفحه چاپ QR.

### امنیت (دموی تعاملی)
- [ ] با `admin2@demo.cafe` وارد شوید؛ فقط محصولات «کافه شهر» قابل مشاهده است؛ تغییر ID در هیچ فرمی ممکن نیست (cafe_id همیشه از context سمت سرور می‌آید).
- [ ] باز کردن مستقیم `/superadmin` با حساب مدیر کافه → ریدایرکت به `/admin`.
- [ ] خروج → دسترسی به `/admin` به `/login` ریدایرکت می‌شود.

### اشتراک
- [ ] در پنل ابرمدیر، اشتراک کافه لم را «expired» کنید → منوی عمومی پیام انقضا؛ نوشتن محصول در داشبورد مسدود.
- [ ] «suspended» → منو غیرفعال. «cancelled» → پیام لغو. برگرداندن به active بدون از دست رفتن داده.
- [ ] پس از انقضا، محصولات/تصاویر/تنظیمات سر جایشان هستند (تأیید حفظ داده).

### آمار
- [ ] چند بار منو را باز کنید؛ یک بازدید در روز ثبت می‌شود (dedup) و نمودار ۷ روز به‌روز می‌شود.
- [ ] باز کردن جزئیات محصول → «نمایش محصولات» و رتبه‌بندی (پلن حرفه‌ای) رشد می‌کند.

## ۴) معیار پذیرش MVP
معیارهای ۱۲گانه بخش «Final Acceptance Criteria» پرامت پروژه با موارد بالا پوشش داده می‌شود؛ موارد دیتابیسی (ایزولاسیون، سقف پلن، وضعیت اشتراک) هم با pgTAP و هم در دموی تعاملی قابل راستی‌آزمایی هستند.
