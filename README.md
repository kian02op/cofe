# منوکده — پلتفرم SaaS منوی دیجیتال چندکافه‌ای (MVP)

پلتفرمی که به چند کافه اجازه می‌دهد هر کدام **منوی دیجیتال اختصاصی**، **آدرس عمومی یکتا**، **داشبورد مدیریت امن**، **QR Code**، **اشتراک Base/Professional** و **آمار بازدید** داشته باشند — با رابط فارسی راست‌به‌چپ.

> **استک (طبق درخواست پروژه):** HTML5 + CSS3 + Vanilla JavaScript (ES Modules) در فرانت · Supabase (PostgreSQL، Auth، RLS، Storage، Edge Functions) در بک‌اند · استقرار روی Cloudflare Pages یا هر هاست استاتیک دیگر. هیچ فریم‌ورک فرانت‌اندی (React/Vue/...) استفاده نشده است.

## راه‌اندازی سریع (حالت دمو)

بدون هیچ بک‌اندی قابل اجراست:

```bash
npx serve public        # یا: python3 -m http.server 8000 -d public
```

وقتی `config.js` خالی باشد، برنامه با **بنر «حالت نمایشی»** و دیتای نمونه‌ی محلی (localStorage) اجرا می‌شود:

| نقش | ایمیل | گذرواژه |
|---|---|---|
| مدیر کافه «کافه لم» (پلن حرفه‌ای) | `admin@demo.cafe` | `demo1234` |
| مدیر کافه «کافه شهر» (پلن پایه) | `admin2@demo.cafe` | `demo1234` |
| ابرمدیر پلتفرم | `super@demo.cafe` | `super1234` |

دیتای دمو فقط برای ارزیابی UI است و **هرگز** با دیتای واقعی اشتباه گرفته نمی‌شود (بنر + seed جداگانه + پیام در صفحه ورود).

## راه‌اندازی واقعی با Supabase

### ۱) ساخت پروژه Supabase
1. در [supabase.com](https://supabase.com) یک پروژه بسازید (Region نزدیک کاربران، مثلاً Bahrain/Frankfurt).
2. **Project Settings → API** را باز کنید: `Project URL` و `anon public key` را کپی کنید. (`service_role` را هرگز در فرانت نگذارید.)

### ۲) اعمال اسکیما
در **SQL Editor** به ترتیب اجرا کنید (یا با CLI: `supabase db push`):

1. `supabase/migrations/20240101000000_init_schema.sql`
2. `supabase/migrations/20240101000100_functions_triggers.sql`
3. `supabase/migrations/20240101000200_rls_policies.sql`
4. `supabase/migrations/20240101000300_storage.sql`
5. `supabase/migrations/20240101000400_plan_limits_seed.sql`
6. `supabase/migrations/20240101000500_analytics_view.sql`
7. *(اختیاری دمو)* `supabase/seed_demo_cafe.sql`

### ۳) پیکربندی Authentication
- **Authentication → Providers → Email**: فعال بماند.
- **Authentication → Providers → Email → «Allow new users to sign up» را خاموش کنید.** ثبت‌نام عمومی وجود ندارد؛ حساب‌ها فقط توسط ابرمدیر (تابع `admin-create-user`) ساخته می‌شوند.
- اگر می‌خواهید ورود فقط از دامنه خودتان باشد، دامنه را در **URL Configuration → Site URL** تنظیم کنید.

### ۴) دیپلوی Edge Functions

```bash
supabase functions deploy admin-create-user
supabase functions deploy track --no-verify-jwt
supabase secrets set ALLOWED_ORIGINS="https://menu.example.com"
supabase secrets set ANALYTICS_PEPPER="<یک رشته تصادفی طولانی>"
```

- `ALLOWED_ORIGINS`: فقط دامنه(های) سایت شما به `track` دسترسی داشته باشند (CORS).
- `ANALYTICS_PEPPER`: نمک هش روزانه بازدیدکننده (هیچ IP/UA خام ذخیره نمی‌شود).

### ۵) پیکربندی فرانت

`public/config.js` را پر کنید:

```js
window.APP_CONFIG = {
  SUPABASE_URL: "https://xxxx.supabase.co",
  SUPABASE_ANON_KEY: "eyJ...",
  SITE_URL: "https://menu.example.com",
};
```

یا برای دیپلوی با متغیر محیطی، `scripts/build.mjs` را اجرا کنید که `.env` را در `config.js` می‌ریزد:

```bash
cp .env.example .env    # مقادیر را پر کنید
node scripts/build.mjs  # config.js را می‌سازد (قبل از دیپلوی)
```

مقادیر «امن برای فرانت»: `SUPABASE_URL` و `SUPABASE_ANON_KEY` (این کلید عمومی است و امنیت با RLS تضمین می‌شود).
مقادیر «فقط سمت سرور»: `service_role key`، `ANALYTICS_PEPPER` (فقط در Secrets توابع Edge).

## اولین ابرمدیر پلتفرم

ثبت‌نام عمومی وجود ندارد؛ اولین ابرمدیر را به‌صورت امن بسازید:

1. در **Authentication → Users → Add user** یک کاربر با ایمیل/گذرواژه قوی بسازید (Auto Confirm: بله).
2. در **SQL Editor**:

```sql
update public.profiles
set platform_role = 'super_admin'
where id = '<AUTH_USER_UUID>';
```

`platform_role` با تریگر دیتابیس (`protect_platform_role`) در برابر تغییر از سمت کلاینت قفل است؛ فقط همین SQL (یا service role) می‌تواند آن را تغییر دهد.

## ساخت کافه و مدیر کافه

با حساب ابرمدیر وارد `/superadmin` شوید:

- **«کافه جدید»**: نام، slug (آدرس عمومی)، پلن، تاریخ انقضا و **حساب مدیر کافه** (ایمیل/گذرواژه) را وارد کنید. ساخت حساب کاربر از طریق Edge Function `admin-create-user` انجام می‌شود که دسترسی ابرمدیرِ فراخوان را سمت سرور بررسی می‌کند.
- پس از ساخت: دکمه **اشتراک** برای تغییر پلن/وضعیت/انقضا و دکمه‌های تعلیق/فعال‌سازی/لغو.
- مدیر کافه با همان ایمیل/گذرواژه در `/login` وارد داشبورد `/admin` می‌شود.

## اجرا و استقرار

### لوکال
```bash
npx serve public
# منو:      http://localhost:3000/cafe/demo-cafe  (بعد از seed دمو)
# ورود:     http://localhost:3000/login
```

### استقرار روی Cloudflare Pages
1. ریپو را به Cloudflare Pages وصل کنید.
2. **Build command:** `node scripts/build.mjs` (اگر از env استفاده می‌کنید) · **Build output directory:** `public`
3. متغیرهای محیطی Build: `SUPABASE_URL`, `SUPABASE_ANON_KEY`, `SITE_URL` را ست کنید.
4. دامنه اختصاصی را در Custom Domains وصل و `SITE_URL` را با همان مقدار به‌روز کنید (QR بر اساس `SITE_URL` ساخته می‌شود).
5. در Supabase: `ALLOWED_ORIGINS` را با دامنه جدید ست کنید و **Authentication → URL Configuration** را به‌روز کنید.

جزئیات بیشتر: [`docs/DEPLOYMENT.md`](docs/DEPLOYMENT.md)

## مدل اشتراک و محدودیت‌ها

| | **پایه (Base)** | **حرفه‌ای (Professional)** |
|---|---|---|
| محصول فعال | ۵۰ | ۲۰۰ |
| دسته‌بندی | ۱۰ | ۳۰ |
| زبان منو | ۱ (فارسی) | ۳ (فارسی/انگلیسی/...) |
| برچسب محصول (محبوب/جدید/ویژه) | — | ✓ |
| تم پیشرفته (پس‌زمینه تیره، سبک کارت، سبک هدر) | — | ✓ |
| تحلیل پیشرفته (بازه تاریخ، رتبه‌بندی) | — | ✓ |
| سقف فایل تصویر / حجم کل | ۲MB / ۵۰MB | ۴MB / ۵۰۰MB |

- **تک منبع حقیقت:** همه سقف‌ها در جدول `plan_limits` هستند و **تریگرهای دیتابیس** آن‌ها را اعمال می‌کنند (`PLAN_LIMIT_*`). فرانت فقط همان‌ها را برای نمایش پیام ارتقا می‌خواند؛ دور زدن UI هیچ سودی ندارد.
- **وضعیت‌ها:** `trial` / `active` / `expired` / `suspended` / `cancelled` — رفتار دقیق هر وضعیت در `cafe_service_state()` پیاده و مستند شده:
  - `active`: منو و داشبورد عادی.
  - `expired`: منوی عمومی پیام «اشتراک منقضی» می‌دهد؛ نوشتن در داشبورد قفل (فقط مشاهده تنظیمات/اشتراک).
  - `suspended`: منو غیرفعال؛ دسترسی داشبورد محدود.
  - `cancelled`: دسترسی فوری قطع؛ **هیچ داده‌ای حذف نمی‌شود** و ابرمدیر می‌تواند هر زمان بازیابی کند.
- در MVP، پرداخت/درگاه وجود ندارد؛ اشتراک‌ها دستی توسط ابرمدیر مدیریت می‌شوند.

## امنیت

- **RLS روی همه جدول‌ها**؛ کاربر ناشناس فقط به `public_menu_*` (viewهای عمومیِ از قبل فیلترشده) دسترسی دارد و هیچ INSERT عمومی روی جدول‌های مدیریتی وجود ندارد.
- **ایزولاسیون کامل کافه‌ها** با `is_cafe_member()` (SECURITY DEFINER) — کافه A به داده کافه B دسترسی ندارد (تست: `supabase/tests/rls_tests.sql`).
- **بدون ثبت‌نام عمومی**؛ ارتقای خودبه‌خودی به ابرمدیر غیرممکن است (`platform_role` قفل).
- **عملیات ممتاز** (ساخت کاربر) فقط از Edge Function با توکن ابرمدیر.
- **اعتبارسنجی دوسویه** (کلاینت + تریگر/پالیسی دیتابیس)، محدودسازی نوع/حجم/حجم تجمعی تصاویر داخل دیتابیس (`enforce_cafe_asset_rules`)، رد SVG و فایل‌های غیرتصویری (ضد XSS)، escape امنِ متن کاربر (رندر فقط با `textContent`/DOM API).
- چک‌لیست کامل: [`docs/SECURITY-CHECKLIST.md`](docs/SECURITY-CHECKLIST.md)

## آمار (Analytics)

- رویدادها: `menu_view` (یک بار به‌ازای بازدیدکننده در روز)، `product_view`، `category_view`، `search`.
- ثبت فقط از طریق Edge Function `track`: اعتبارسنجی سخت، Rate-limit، سقف روزانه، و **بدون هیچ داده شخصی** (IP/UA خام ذخیره نمی‌شود؛ فقط هش روزانه‌ی نمک‌دار برای حذف تکرار).
- **این آمار «بازدید منو» است نه فروش** — سفارش آنلاین در MVP وجود ندارد.
- نمایش: پایه = نمودار ۷ روز؛ حرفه‌ای = بازه‌های ۷/۳۰/۹۰ روز + پرطرفدارترین دسته‌ها/محصولات (تجمیع سمت دیتابیس با view `analytics_daily`).

## تصاویر و Storage

- باکت عمومی `cafe-assets` با مسیرهای تفکیک‌شده بر اساس کافه: `cafes/{cafe_id}/branding|products/{uuid}.{ext}`.
- آپلود/حذف فقط برای عضو همان کافه (پالیسی مسیر-محور). منوی عمومی تصاویر را از URL عمومی نمایش می‌دهد؛ هیچ فایل خصوصی در این باکت نیست.
- هنگام جایگزینی/حذف محصول، فایل قبلی حذف می‌شود (ضد فایل بی‌نشان)؛ اسکریپت پاک‌سازی دوره‌ای در `docs/DEPLOYMENT.md`.

## پشتیبان‌گیری و بازیابی

- **دیتابیس:** در داشبورد Supabase → Database → Backups (پلن‌های Pro اگر PITR دارند فعال کنید). بازیابی: بازگردانی همان snapshot.
- خروجی دستی داده‌های یک کافه:
```sql
copy (select * from products where cafe_id = '<uuid>') to stdout csv;
```
- **Storage:** باکت را با `supabase storage sync` یا ابزار S3-compatible خارجی دوره‌ای sync کنید.
- حذف‌ها در سطح کافه به‌صورت cascade است؛ قبل از حذف نهایی، تعلیق را ترجیح دهید (داده حفظ می‌شود).

## وضعیت پیاده‌سازی

**پیاده‌سازی‌شده و تست‌شده:**
- منوی عمومی: هدر/لوگو/کاور، تم داینامیک، جستجو، دسته‌بندی، برچسب‌ها، حالت ناموجود، چندزبانه (fa/en)، حالت‌های منقضی/معلق/یافت‌نشده، ردیابی بازدید.
- داشبورد کافه: CRUD محصول (تصویر، قیمت، موجودی، ترتیب، فیلتر/جستجو)، CRUD دسته با حذف امن (انتقال/حذف محصولات)، تنظیمات کامل کافه (slug با تأیید، زبان‌ها با سقف پلن، ارز/تومان‌سازی، ساعات کاری، شبکه‌ها)، ویرایشگر ظاهر با پیش‌نمایش زنده، QR (دانلود PNG + صفحه چاپ)، آمار، اشتراک و متر مصرف.
- پنل ابرمدیر: آمار کلی، ساخت کافه + حساب مدیر (Edge Function)، جستجو/فیلتر، ویرایش، تعلیق/فعال‌سازی/لغو، مدیریت کامل اشتراک (پلن/وضعیت/تمدید +۳۰/+۹۰/+۳۶۵)، شمارش محصولات/دسته‌ها.
- امنیت: RLS کامل + viewهای عمومی + تریگرهای سقف پلن + قفل وضعیت اشتراک + سهمیه تصویر + Edge Functionهای امن.
- تست: ۱۴ تست واحد Node (پاس) + ۹ تست pgTAP ایزولاسیون/سقف برای اجرا روی پروژه واقعی.
- مستندات: استقرار، امنیت، تست.

**خارج از محدوده MVP (عمداً):** سفارش آنلاین، سبد خرید، درگاه پرداخت، POS، برنامه وفاداری، وب‌سوکت/Realtime، ایمیل دعوت‌نامه خودکار.

**محدودیت‌های شناخته‌شده:**
- مرتب‌سازی با دکمه بالا/پایین (Drag&drop اضافه نشده).
- سقف پلن فقط از سمت دیتابیس + پیام فرانت؛ صفحه «ارتقا» پرداخت ندارد (تماس با مدیر پلتفرم).
- ترجمه محتوا فعلاً fa/en؛ ساختار جداول برای زبان‌های بیشتر آماده است.
